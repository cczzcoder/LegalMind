# LegalMind 前端界面说明

> 本文是前端的**规格与验收依据**：每个页面的功能范围、关键交互行为、验收标准。
> 实现与本文不一致时以本文为准（或先改本文再改代码）。
> 后端接口以设计文档第 13 节与 `GET /openapi.json` 为准；本文只写**前端怎么用**。

## 1. 定位与边界

前端是**机构内部的法律资料管理与研究工具**的界面，不是面向公众的产品。三条硬约束决定了界面的写法：

1. **结论永远要带证据与边界**（设计 §9.2、§9.3）：回答里必须能看见引用了哪一条、哪一版、什么效力状态；
   门禁没过的结论**不能长得像结论**。
2. **不提供法律服务**（§20.2）：每个正式输出都要带免责声明；个性化提问不给个人结论。
3. **客户数据不落库**（§21）：问答的正文只在短期缓存里，界面要如实显示「内容不可用」而不是留空。

## 2. 技术选型与理由

| 选型 | 理由 |
| --- | --- |
| React 18 + TypeScript + Vite（既有） | 不换栈 |
| Ant Design 5（既有） | 已有依赖；`Layout`/`Grid.useBreakpoint` 直接支撑响应式 |
| **路由：自写 hash 路由**（`src/app/router.tsx`，约 60 行） | 需要深链（运行 id 可分享、刷新不丢）与前进后退，但只有 6 个页面。**不引入 react-router**：本项目对依赖的口径是「没有测量支撑就不装」（拒绝 Elasticsearch / Neo4j / LangGraph 同口径）。路由表集中在一个文件，将来换 react-router 是受控改动——**触发点是出现嵌套路由或路由级数据加载**。 |
| **状态：React Context + 页面级 state**（`src/app/session.tsx`） | 只有「会话」是跨页共享的。**不引入 Redux / TanStack Query**：列表数据都是一次性拉取，`useAsync` 够用；引入查询库要连带缓存失效策略，收益不抵复杂度。 |
| **SSE：浏览器原生 `EventSource`** | 问答进度用 `GET /answers/{id}/events`；`EventSource` 自带断线重连，且 GET 不需要 CSRF 头、Cookie 同源自动带上。 |
| 日期格式化：`dayjs` | Ant Design 5 的传递依赖，**不新增**。 |
| **不用表格**（`Table`） | 记录列表一律用**卡片列表**。表格在窄屏会退化成横向滚动，那样就得维护「宽屏表格 / 窄屏卡片」两套渲染；卡片天然纵向，一套就够。代价是宽屏信息密度略低——对这个规模的数据量不构成问题。 |
| 页面组件**默认导出**，组件与 hooks **命名导出** | 路由懒加载（`React.lazy`）要求默认导出，这是约定俗成的分界。 |
| 数据与组件分文件（`statusLabels.ts` / `StatusTag.tsx`） | `react-refresh` 要求「一个文件只导出组件」，否则热更新整页刷新。分开之后也便于别处只取文字或只取组件。 |

`App.tsx` 里另有一段**开发期自检**：导航表里每一条路由都必须有渲染分支，否则控制台报错——
防止新加页面时静默 404。

## 4. 响应式策略

断点用 Ant Design 的 `Grid.useBreakpoint()`（与 CSS 媒体查询同源，避免两套断点打架）。

| 断点 | 宽度 | 布局 | 关键变化 |
| --- | --- | --- | --- |
| `xs` / `sm` | < 768 | 顶栏 + **抽屉导航**；单列 | 表格降级为**卡片列表**；操作按钮收进「更多」；长文本换行不断词 |
| `md` | 768–991 | 顶栏 + **抽屉导航**（与 `xs`/`sm` 同形态） | 双列可行；内容区更宽（没有固定侧栏占位） |
| `lg` / `xl` | ≥ 992 | **固定侧栏 208px** + 内容区 | 列表 + 详情双栏（问答、Wiki） |

通用规则：

- **触控目标 ≥ 44×44 px**（`< lg` 的**可点击控件**：按钮、图标按钮、菜单项、导航链接）。
  lg 以上是桌面、鼠标精度足够，**保持 antd 默认的 32px**——否则整页按钮都会变笨重。
  落地在 `src/style.css` 一条 `@media (max-width: 991px)`（断点与 `AppShell` 的
  `useDrawer = !screens.lg` 同源）：**只撑大盒子，不动图标与文字的字号**。
- **不使用表格**（见 §2）：记录列表一律卡片，所以没有「表格降级」这套额外逻辑
- 内容区最大宽度 1280px，超宽屏不拉满
- 长 id、条号、条款文本：`overflow-wrap: anywhere`，不出现横向滚动条
- 尊重 `prefers-reduced-motion`（Ant Design 的 `motion` 开关）

**抽屉导航（`< lg`）的交互规范**：

- **默认关闭**，只由顶栏汉堡按钮打开（`aria-label="打开导航"`）
- **点击遮罩关闭**，`Esc` 也关闭（antd `Drawer` 的默认行为，不要关掉）
- **点菜单项后自动关闭**——否则跳转完抽屉还挡着内容
- 宽度 **248px**（固定侧栏是 208px，两者**不是**同一个宽度）
- 打开时锁定页面滚动、关闭后焦点回到汉堡按钮（同样交给 antd 的 `Drawer`）

## 5. 页面规格

### 5.1 登录 / MFA（`#/login`）

**功能范围**：用户名密码登录；管理员账号的 TOTP 绑定（首次）与验证（之后）；恢复码展示与提示；登出。

**关键交互**：

- 未登录访问任何路由 → 重定向到 `#/login`，并记住原目标，登录后跳回
- 登录成功后按 `mfa_status` 分流：`ok` → 目标页；`enroll` → 绑定向导；`verify` → 验证码输入
- **恢复码只在绑定成功时显示一次**，界面明确提示「离线保存、每码一次」，不持久化
- 验证码输入框：`autoComplete="one-time-code"`、`inputMode="numeric"`、自动聚焦
- 登出：调 `POST /auth/logout` 后清空会话状态（**无论成败都清**）

**验收标准**：

1. 刷新页面能凭 Cookie 恢复登录态（`GET /auth/me`）；未登录时不报错、不闪烁
2. 绑定流程：开始绑定 → 展示密钥与 otpauth 链接（可复制）→ 输入 6 位码 → 成功 → 展示恢复码
3. 验证码不足 6 位时提交按钮禁用；提交中禁用重复提交
4. 登录失败显示服务端返回的 `message`，不泄露「用户是否存在」
5. 移动端（< 768）表单单列、输入框宽度 100%、按钮占满一行

### 5.2 问答（`#/ask`，核心）

**功能范围**：提交问题（异步运行）；展示我提交的运行列表与状态；进入某次运行看进度与结果。

**关键交互**：

- 提交后**立刻**拿到运行 id 并跳到 `#/answers/{id}`；不在提问页等结果
- 页首有一条**会话栏**：显示「当前会话已问 N 轮」并提供「开始新会话」（见 §5.7）
- 问题输入：`Enter` 提交、`Shift+Enter` 换行；长度 1–2000，实时字数
- 高级参数（取多少条依据、最大生成 token、覆盖模型）折叠在「高级」里，默认不打扰
- 运行列表显示：状态、是否发布、门禁、证据条数、时间；**在等用户补充**的运行单独标出
- 空态：没有运行记录时给出「先问一个」的引导，而不是空白表格
- 未配置短期缓存（`POST /answers` 返回 503）时，**如实提示这是部署配置问题**，并建议改用检索页

**验收标准**：

1. 提交后 1 秒内跳转到运行页，且 URL 可直接分享/刷新（刷新后能继续看到结果）
2. 运行列表在 `< md` 下是卡片列表，不是横向滚动表格
3. 503（未配缓存）时页面给出可操作的解释，不显示原始错误码
4. 问题文本**不出现在任何请求 URL 里**（它只在 POST body 中）
5. **普通提问者（`reader`）也能看到自己的运行列表**：列表里是**我提交的**运行，**不含同事的**
   （设计 §9.4，V1.31 修正——此前该接口两种模式都要求 `review.decide`，读者直接 403）。
   待审队列（§5.4）才需要 `review.decide`

### 5.3 单次运行（`#/answers/{id}`，核心）

**功能范围**：订阅 SSE 展示进度；终态时展示结论或拒答说明；澄清请求的展示与补充；人工复核。

**关键交互**：

- 进入即订阅 `GET /answers/{id}/events`：
  - `state` → 顶部**状态时间线**（`CREATED → RETRIEVING → …`），已过步骤打勾
  - `answer` → 渲染结论块：**正文 + 引用列表 + 各类 notice + 免责声明**
  - `clarify` → 渲染澄清块：问题 + 候选项（可点选填入补充框）+ 「补充并继续」按钮
  - `timeout` → 明确提示「仍在后台运行」并给出「重新连接 / 直接查询」
  - `done` → 关闭连接
- **处理中给时间量级**（非终态时显示「正在处理」卡片）：**已用时间**（真实，按运行记录的
  `created_at` 算——**刷新页面后仍然准**）+ **预计量级**（按阶段经验值**粗估**，界面上写明
  「不是精确预测」）+ 进度条。⚠️ **进度条刻意不到 100%**（到了 100% 还在转比停在 80% 更可疑）；
  **超过预算如实说「比预计慢一些」**，不显示「还需 0 秒」也不干脆不显示
- **门禁未过的结论必须长得不一样**：`published=false` 时用警示色边框 + 「这不是正式结论」字样，
  并把拒答说明与草稿（若有）分区展示
- 引用逐条可点：显示法名、条号、**效力状态**、版本 id；效力状态非现行有效的要标红
- 澄清补充：提交后**复用同一个运行**，界面提示「已提交，正在继续」，并重新订阅
- 复核（需 `review.decide`）：填写备注 → 提交；已复核的运行显示复核人、时间、备注，按钮禁用
- **继续追问**（§5.7）：终态时出现该卡片——会话轮次（可点回前几轮）+ 追问输入框；提交后
  **新开一次运行**（不是续跑澄清那条路），并跳到它
- 离开页面**必须关闭 EventSource**（防止连接泄漏）

**验收标准**：

1. 状态时间线随事件**逐个出现**（不是一次性全部出现）；能看出当前进行到哪一步
2. `published=false` 的结论**视觉上明显区别于**正式结论，且带「未通过门禁（原因）」文字
3. 澄清：点候选项能填入补充框；提交后状态从 `CLARIFYING` 前进到 `RETRIEVING`（同一条时间线）
4. 内容不可用（缓存过期/未配置）时显示「内容不可用」+ 原因说明，**不显示空白或假内容**
5. 卸载页面后不再有进行中的 SSE 连接（DevTools Network 可见）
6. 移动端：引用列表与结论纵向堆叠，不出现横向滚动

### 5.4 待审队列（`#/review`）

**功能范围**：列出 `NEEDS_REVIEW` 且未复核的运行；进入详情复核。

**关键交互**：

- 仅对持有 `review.decide` 的角色显示入口；其他角色访问 → 提示无权限（不显示空表）
- 列表按时间升序（先来先审）；显示门禁原因、证据条数、提交人
- 支持「只看未复核 / 全部」切换
- 一键进入详情复核（复用 5.3 的复核块）

**验收标准**：

1. 无权限角色看不到入口；直接访问路由时显示明确的权限提示，而不是报错
2. 队列为空时显示「没有待审运行」
3. 复核后该条从「未复核」列表消失，且详情里能看到复核记录

### 5.5 检索（`#/search`）

**功能范围**：自然语言/关键词检索条款；展示命中条款、效力状态、版本、原文定位锚点。

**关键交互**：

- 单一搜索框 + 结果列表；输入为空不请求
- 结果卡片：法名 + 条号 + 效力状态标签 + 条款正文（可展开/收起）+ 版本信息
- **效力状态非现行有效的置顶警示**（这是设计 §8.3 的核心）
- 支持按资料类型/效力状态筛选（对应 `POST /search` 的过滤字段）
- 无命中时提示「没有命中，换个说法或补充关键词」，并给出**去问答页**的引导

**验收标准**：

1. 检索结果里的条款正文与后端返回一致（不截断、不改写）
2. 效力状态标签颜色符合中文语境约定（红色=上涨在本项目不适用；这里用**警示色表示「非现行有效」**）
3. 空查询不发请求；请求中显示骨架屏
4. 移动端卡片单列，正文默认折叠 3 行

### 5.6 Wiki（`#/wiki`、`#/wiki/{pageId}`）

**功能范围**：页面列表；草稿编辑与保存新修订；修订历史；引用编辑；提交审核 / 发布 / 驳回；
失效标记（`review_due_at`）。

**关键交互**：

- 列表 + 编辑双栏（≥ `lg`）；窄屏为「列表 → 详情」两级
- **编辑冲突**：保存带 `expected_revision`；409 时提示「先自行保留未保存文字，再重新打开」，
  **不自动合并**（与后端一致）
- 修订历史：逐条显示序号、状态、时间、正文
- 引用：可增删条款引用（绑定到条款版本）；**发布前至少一条引用**（后端强制，前端提前提示）
- 审核动作按权限与状态显示：`draft → 提交审核`；`submitted → 发布 / 驳回`（需 `review.decide`，
  **作者不能审自己的修订**——前端据此隐藏按钮并说明原因）
- 失效页面（`review_due_at` 非空）在列表与详情都打标，并显示原因

**验收标准**：

1. 作者打开自己提交的修订时，「发布/驳回」按钮**不出现**，并有文字说明原因
2. 保存冲突（409）时给出明确指引，且**不丢用户已输入的内容**
3. 发布前无引用时，按钮禁用并提示「至少一条引用」
4. 失效标记在列表可见，点开能看到 `review_due_reason`
5. 窄屏下编辑区可用（不出现横向滚动）

⚠️ **引用目前只能粘贴条款版本 id**（在「条款检索」结果里可复制）——**没有「从检索结果直接引用」的选择器**。
接口只接受 `provision_version_ids`，做一个选择器要么跨页暂存、要么加一个搜索弹窗，两者都是独立的一轮。

### 5.7 会话与多轮追问（设计 §9.6、需求 FR-16）

**功能范围**：同一会话内的追问继承上文（「那如果是这样呢？」），用户不必重复已说过的条件。

**关键交互**：

- **会话 id 不进 URL、不进 Cookie**（设计 §9.6）：存在 `sessionStorage`，**刷新不丢、关标签页就散**
- **问答页默认在会话里提问**：第一次提交即开会话。⚠️ **这是必需的**——第一轮不带 `session_id` 的话，
  运行详情页的追问就补不出自足的问题（后端不知道上文）。所以页面上给一个显式的「开始新会话」，
  **问不相干的问题前该点它**——否则上一轮的上下文会把检索带偏
- **继续追问**在运行详情页的终态出现：列出本会话的轮次（当前那轮加粗、其余可点回），输入框提交后
  **新开一次运行**并跳过去
- 轮次列表**只存在浏览器本地**，用来给用户一个「回到前几轮」的入口

**验收标准**：

1. 提交后 URL 的 hash **只有运行 id**，没有会话 id 或问题文本
2. 追问后新运行的结论与上一轮一致（说明上文真的带上了）；不带会话时同一句追问会检索到无关条文
3. 会话轮次在窄屏下**纵向堆叠**、不出现横向滚动
4. 点「开始新会话」后轮次清空，下一次提问从第 1 轮开始

**已知限制**：

- ⚠️ **轮次列表只看得到本浏览器提交的**——换标签页或换设备看不到历史。**这是有意的取舍**：列运行列表要
  `review.decide`（普通提问者没有这个权限），而「会话列表」在设计里就是「不做」（§9.6）。
  **要跨设备看会话，得先有「按会话查运行」的接口与权限**，那是另一轮的事。
- ⚠️ **上下文只取最近 1 轮**（后端决定，§9.6），**不做指代消解**——「它」「该条」指哪一条，界面不猜。
- ⚠️ **界面不显示「补全后的自足问题」**：后端 `Answer` 里有 `resolved_question`，但接口只回传缓存里的
  原始问题。想知道系统实际拿哪句话去检索，目前要看运行记录的配置快照或日志。

### 5.8 文献管理（`#/documents`）

**功能范围**：导入原件、看原件列表与解析进度。**只做导入必经的两条链路**（上传 + 进度）；
来源登记/编辑、原件下载、授权名单**不在本轮**（见 §5.9）。

**关键交互**：

- 上传卡片（**有 `document.write` 才渲染**）：选来源 → 选敏感级别 → 选访问范围 → 选文件 → 「导入并解析」
- 提交后：`POST /documents` 返回 **202**——原件**已登记**，而解析任务**只是登记了、还没跑**。
  页面立刻刷新原件列表，并开始**每 2 秒轮询** `GET /jobs/{id}`
- 进度告警：排队中 / 解析中 / 等待重试 / **已完成** / 失败 / 已取消；失败时按 `error_code` 说人话
  （`resource_exhausted` 是**资源不足**，不是业务结果，FR-13）
- 原件列表：卡片（不用表格，§2），显示来源、格式与大小、敏感级别与访问范围、SHA-256、导入时间

**验收标准**：

1. **导入的是原件、不是解析产物**：上传后立刻能看到原件卡片，但「能检索」要等解析完成
2. 解析失败**不能显示成成功**——按 `error_code` 给可操作的解释
3. 无 `document.write` 的角色**看不到上传卡片**，但看得到原件列表（强制校验永远在后端）
4. 窄屏（< 768）上传表单单列、列表卡片单列，不出现横向滚动

**已知限制**：

- ⚠️ **上传走 `application/octet-stream` 裸字节，不是 multipart**（后端 `read_body` 直接读裸字节）——
  所以 `client.ts` 改成「调用方指定了 `Content-Type` 就不覆盖」
- ⚠️ **同一份文件重复导入返回 409**（`sha256` 唯一）。**撤下原件后同一份文件再也导不进来**——
  任务幂等键由 `sha256` 派生，而撤下不清理任务行（见设计 §7 的已知问题）
- ⚠️ **来源只能选已登记的**：没有来源就得先用 CLI `create-source` 登记（界面的来源登记不在本轮）

## 6. 关键约定

- **错误呈现**：服务端统一错误体是 `{ code, message, trace_id }`（**不是 FastAPI 的 `detail`**）。
  界面显示 `message`，并把 `trace_id` 以可复制的小字附上——排查时要用。
- **CSRF**：所有非 GET 请求带 `X-CSRF-Token`（仅存内存）；401 时清空会话并跳登录。
- **权限**：前端只做**显示层**判断（决定要不要渲染入口），**强制校验永远在后端**。
  任何权限判断都要带注释说明这一点（沿用 CODE_REVIEW m6 的结论）。
  **m6 的根因已修**：前端不再复制「角色→权限」映射——后端在 `CurrentUser.permissions` 里
  直接给出**权限集合**（`authorization.permissions_for`），前端只用 `can("document.read")` 这类判断。
  这样后端改权限时前端自动跟上，不会像 m6 描述的那样「后端改了、前端提示还停在旧名单」。
- **合规文案**：免责声明与「不提供法律服务」的说明集中在 `NoticeBar`，**不在各页各写一遍**。
- **时间**：统一 `dayjs` 本地化格式，不用裸 `Date.toLocaleString()`（跨浏览器不一致）。
