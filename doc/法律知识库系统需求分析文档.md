# LegalMind 法律知识库系统需求分析文档

**文档版本**：V1.1  
**文档状态**：待评审  
**系统名称**：LegalMind  
**系统定位**：准确性优先、可追溯、支持版本化 Wiki 的法律知识管理与辅助研究系统

---

## 1. 项目目标
建设一个基于 Python 的法律知识库系统，统一管理法律原始资料、条款版本、专业 Wiki、检索与辅助问答。

**系统遵循以下优先级：**

```
数据与权限安全 → 证据可靠 → 时间及适用范围匹配 → 回答准确 → 可解释与可追溯 → 响应速度
```

**核心原则**：允许增加检索、验证和人工审核时间，不允许为追求速度跳过必要的证据与权限检查。

### 1.1 核心目标
- 保存可核验的原始资料和来源信息
- 支持法律文件及条款的历史版本查询
- 提供精确检索、关键词检索和语义检索
- 提供带具体依据、适用条件和不确定性说明的问答
- 建立支持引用、修订、审核和更新提醒的 Wiki
- 实现访问控制、关键操作审计及备份恢复
- 建立持续评测与回归测试机制

### 1.2 系统边界
系统提供法律资料管理与研究辅助，**不将模型输出标记为未经审核的最终专业意见**。

**以下事项不属于第一版目标：**

- 自动代理诉讼或执行外部法律行为
- 无人审核发布 AI 生成的专业知识
- 自动解决所有法律冲突及复杂适用性问题
- 全法域、全类型法律资料的完整覆盖
- 多智能体自主工作流
- 大规模分布式图数据库
- 自动微调法律大模型

## 3. 用户角色与权限

| 角色 | 主要能力 |
| --- | --- |
| 阅读用户 | 查询授权资料、阅读已发布 Wiki、使用问答 |
| 内容编辑 | 导入资料、校正解析、编辑 Wiki 草稿 |
| 法律审核员 | 审核资料版本、Wiki 和待审回答 |
| 知识管理员 | 管理分类、来源、引用关系和更新任务 |
| 系统管理员 | 管理部署、账号、配置和任务运行 |
| 审计人员 | 在授权范围内查看审计和追溯记录 |

**权限要求：**

- 系统管理权限不自动等于全部业务内容访问权限
- 权限粒度至少到文档及 Wiki 页面
- 同一人员可以具备多个角色，但高风险发布默认不得自行提交、自行审批
- API、管理后台、检索、缓存、导出和文件下载执行一致授权规则

## 4. 功能需求

### FR-01 资料来源管理
系统应支持：

- 来源登记、可信等级和授权说明
- 官方原文、转载材料、内部分析等来源类型区分
- 来源地址、发布机关、抓取时间和更新频率记录
- 来源更新检查失败告警
- 来源被撤回、文件被替换或内容发生变化的记录

**约束条件：**

- 不得仅凭文件标题判断权威性
- 每份资料应显示“来源最后核查时间”，不得把资料入库时间当作来源更新时间

### FR-02 资料导入与原始文件保存
支持第一版约定格式的 **PDF、DOCX、HTML 和纯文本**资料。

**导入流程应包含：**

1. 文件类型、大小和完整性检查
2. 恶意文件及异常内容检测
3. 文件哈希及重复检测
4. 来源、权限和敏感级别登记
5. 原文件保存
6. 异步解析及任务状态反馈

**约束条件：**

- 导入失败必须保留原因，允许修复后重试
- 不能产生重复发布记录

### FR-03 文档解析与校正
**系统应提取：**

- 文档标题、章节、条款及正文
- 页码、段落、表格与附件关系
- 原文与解析文本之间的定位关系
- 解析器及 OCR 版本
- 质量检查结果与人工校正记录

**质量要求：**

- 保存原始解析结果，不以人工校正覆盖唯一原件
- 对条号、日期、金额、否定词、表格等设置重点检查
- 低质量解析进入待复核状态
- 无法可靠定位的片段不得伪造页码或字符位置
- 未通过质量门禁的内容不得进入正式问答证据范围

### FR-04 法律文件与条款版本管理
**系统应分别管理：**

- 法律文件的稳定身份
- 法律文件的各个版本
- 条款稳定身份
- 条款在各版本中的文本
- 改号、合并、拆分、替代及删除关系

**时间记录：**

- **业务时间**：公布、生效、失效等时间
- **系统时间**：采集、确认、修正和入库时间

**系统应支持：**

- 指定日期查询候选适用版本
- 历史版本对比
- 条款变更关系浏览
- 未知日期、资料缺口和适用性争议提示
- 过渡条款及特殊适用规则关联

**约束条件：**

- 不得仅依靠日期区间，自动宣告复杂问题的适用法律已经确定

### FR-05 搜索与检索
**检索入口：**

- 法律名称、文号、条号精确查询
- 关键词查询
- 自然语言语义查询
- 历史版本查询
- 来源、法域、类型、时间及权限范围筛选

**结果应显示：**

- 资料名称、类型和来源
- 条款或原文片段
- 版本及状态
- 原文位置
- 来源核查时间
- 适用性或质量警告

**约束条件：**

- 默认保留用户原始查询，查询改写只能补充，不得静默改变金额、时间、主体和法律关系

### FR-06 证据约束问答

**问答流程应支持：**

1. 提取问题中的事实及条件
2. 识别缺失信息
3. 必要时提出澄清问题
4. 检索授权范围内的候选依据
5. 补齐相关定义、例外和引用条款
6. 生成候选答案
7. 执行引用与主张核验
8. 输出答案、有限回答、澄清请求、拒答或转人工结果

**正式答案至少包含：**

- 回答结论
- 已采用的事实或假设
- 关键依据
- 适用条件与限制
- 尚不能确定的事项
- 具体引用及原文入口
- 生成时间和知识范围说明

**严格禁止：**

- 编造文号、条号或引用
- 将资料库未找到等同于法律上不存在
- 将案例中的个别结论直接包装为普遍规则
- 将 Wiki 总结替代原文证据
- 把模型自报置信度作为可靠性证明

### FR-07 拒答与人工复核

系统应区分以下状态：

| 状态 | 含义 |
| --- | --- |
| ANSWERED | 在明确范围内完成回答 |
| PARTIAL | 部分问题可回答，其他部分说明限制 |
| NEEDS_CLARIFICATION | 缺少会改变结论的事实 |
| INSUFFICIENT_EVIDENCE | 未找到足够支持材料 |
| NEEDS_REVIEW | 存在冲突、高风险或适用性疑问 |
| FAILED | 技术故障，不能伪装成证据不足 |

**人工复核触发条件：**

- 具体责任认定
- 个性化期限计算
- 金额计算
- 未解决的依据冲突

风险规则应可配置，并记录触发原因。

### FR-08 Wiki 知识管理

**Wiki 应支持：**

- 专题、概念及术语页面
- 分类、别名和页面间链接
- 断言级引用
- 修订历史、差异对比及回滚
- 编辑、审核、发布及撤回
- 反向引用及更新影响查询

**发布状态：**

```
草稿 → 待审核 → 已发布
             ↘ 退回修改
已发布 → 已撤回
```

**依据状态：**

```
已核验 / 来源有更新 / 待复核 / 依据不足
```

**约束条件：**

- 已发布修订不可直接覆盖
- 回滚应创建新的修订和发布记录
- AI 可以生成草稿，不得自动成为正式知识

### FR-09 更新影响管理

来源或法律版本变化时，应执行以下流程：

1. 保存新版本
2. 标记受影响条款
3. 找出引用该条款的 Wiki 断言
4. 找出受影响的缓存及问答记录
5. 标记待复核
6. 通知相关责任人
7. 经审核后重新发布

**约束条件：**

- 既有回答应保留“当时使用的证据快照”
- 再次查看时应提示证据已更新

### FR-10 认证与授权

**第一版应实现：**

- 登录、退出、会话失效和用户禁用
- RBAC（基于角色的访问控制）
- 文档级和 Wiki 级访问控制
- 管理员强认证
- 失败登录限制
- 下载、导出、审核和发布的独立权限

**安全约束：**

- AI 不得决定用户有权访问哪些资料
- 权限变更后，即使检索索引尚未更新，也不得继续把受限内容发送给模型或用户

### FR-11 审计与追溯

**应记录以下操作：**

- 资料导入、校正及版本调整
- 权限变化
- Wiki 提交、审核、发布及撤回
- 问答所用证据、模型和配置
- 敏感下载和批量导出
- 审计配置及保留政策变化

**隐私保护：**

- 审计内容默认不保存访问令牌、密钥及不必要的敏感正文

### FR-12 评测与反馈

**系统应支持：**

- 人工金标准测试集管理
- 检索、回答、版本及安全专项测试
- 用户反馈与错误分类
- 配置变更前后对比
- 回归测试及发布门禁

**测试要求：**

- 测试集应拆分开发集和独立验收集
- 避免反复调参使验收结果失真

## 5. 非功能需求

以下为建议目标，须经评审和压测确认。

| 类别 | 要求 |
| --- | --- |
| 准确性 | 关键主张必须有可核验证据；证据不足时降低回答范围 |
| 安全性 | 默认拒绝未授权访问，敏感数据不得未经审批外发 |
| 完整性 | 原文、版本、引用和关键审计可追溯 |
| 可维护性 | 模块化单体、显式接口、数据库迁移及版本锁定 |
| 可观测性 | 请求、问答、任务、证据和配置可通过追踪 ID 关联 |
| 可恢复性 | 备份必须通过恢复演练 |
| 性能 | 搜索与问答分开设定目标，不以速度替代核验 |
| 可访问性 | 常用页面支持键盘操作及清晰的错误反馈 |

### 5.1 响应时间建议
在约定数据集及试点并发下：

- **普通检索**：P95 不超过 5 秒
- **问答任务受理**：不超过 2 秒
- **自动核验问答**：P95 暂定不超过 120 秒
- **异步处理**：超时后保留异步任务状态，不直接丢弃请求
- **人工审核**：不纳入自动问答响应指标

### 5.2 恢复目标建议

- **核心数据库目标 RPO**：不超过 1 小时
- **核心数据库及原文访问目标 RTO**：不超过 8 小时
- **全量检索恢复时间**：另行通过索引恢复或重建演练确认

> **注意**：上述指标不是单机部署的天然保证；未配置异机备份和恢复资源前，不宣称达到。

## 6. 验收标准

建议首版建立不少于 **300 条人工审定问题**，覆盖历史版本、例外、事实缺失、无答案、权限和恶意输入等场景。具体数量按业务复杂度调整。

### 6.1 质量指标

| 验收项目 | 初始目标或要求 |
| --- | --- |
| 依据 Recall@20 | 宏平均 ≥ 0.85，按人工标注条款版本计算 |
| 前五结果精度 | 目标 ≥ 0.75，明确相关性及去重定义 |
| 关键主张支持率 | 人工评估目标 ≥ 0.95 |
| 发布引用完整性 | 不存在、越权或无法定位的引用一律拦截 |
| 应拒答问题处理率 | 目标 ≥ 0.90 |
| 可回答问题错误拒答率 | 目标 ≤ 0.10 |
| 版本专项 | 预设关键版本错误案例不得漏过门禁 |
| 权限专项 | 测试中不得出现越权泄露 |
| 审计 | 故障测试后业务、审计和事件记录可对账 |
| 恢复 | 完成至少一次数据库、原文及索引恢复演练 |

### 6.2 报告要求

- 报告样本量、分母、分组结果及不确定性
- 不得只报告平均值，隐藏高风险类别失效
- 数字达标不代表对所有真实问题正确
- RAGAS 指标单独标识，不与传统检索指标混用

> **说明**：RAGAS 的 LLM-based Context Recall 可基于参考答案主张进行评估，定义不同于文档级 Recall@K。参考：[docs.ragas.io](https://docs.ragas.io)
